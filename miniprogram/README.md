# HarborCart 好物港 · 微信小程序

微信原生小程序生活用品商城，复用 HarborCart 的 Spring Boot、MySQL 和 Redis 后端。买家在小程序购物，运营人员可通过已有网页后台处理商品与订单。

## 功能与技术

| 页面 | 功能 |
| --- | --- |
| 发现 | 商品列表、分类、关键词过滤、价格排序、下拉刷新 |
| 商品详情 | 商品介绍、库存状态、数量选择、加入购物车 |
| 购物车 | 数量调整、删除、商品小计、失效商品提示 |
| 确认订单 | 国家与币种选择、收件信息、后端报价、下单与超时恢复 |
| 我的订单 | 状态筛选、成交明细、收件信息、模拟付款、取消、物流单号 |
| 我的 | 登录状态、购物入口、待确认提交恢复、退出登录 |
| 登录注册 | 邮箱密码登录、注册、参数校验、接口错误提示 |

- 客户端使用 JavaScript、WXML、WXSS、原生组件及 `wx.request`，无需安装前端 npm 依赖。
- 后端使用 Spring Boot、Spring JDBC、MySQL、Redis，与网页端共用接口。
- 蓝灰色界面与本地商品插图，包内资源无需访问外部图片服务。
- 登录使用商城邮箱账户。接入微信登录需要真实 AppID、服务端 code 换取会话以及账户绑定逻辑，当前采用邮箱演示账户。
- 付款为模拟流程，汇率为固定演示值，不产生真实扣费。项目没有微信支付接入或上线审核记录。

## 第一次运行

需要 Java 17+、Maven 3.6.3+、Docker Desktop 和微信开发者工具。运行自动验证还需要 Node.js 18+。

在含有 `compose.yml` 的 HarborCart 根目录打开终端。

```powershell
docker compose up -d
cd backend
mvn spring-boot:run
```

后端启动后，浏览器访问 `http://127.0.0.1:8080/api/config` 应返回 JSON。

1. 在微信开发者工具中选择导入项目，目录选到包含 `app.json` 的 `miniprogram` 文件夹。
2. 配置文件默认使用 `touristappid`。工具支持游客模式时可先做本地页面调试，否则填写你自己的小程序 AppID。
3. 确认使用小程序工程，使用工具提供的当前稳定基础库。
4. 本地调试时在“详情 → 本地设置”勾选“不校验合法域名、web-view（业务域名）、TLS 版本以及 HTTPS 证书”。项目配置已设置 `urlCheck: false`。
5. 点击编译，进入“我的”页面登录。

| 角色 | 邮箱 | 密码 |
| --- | --- | --- |
| 买家 | buyer@harborcart.demo | BuyerDemo123! |
| 网页运营后台 | admin@harborcart.demo | AdminDemo123! |

演示账户由后端在 `DEMO_ENABLED=true` 时初始化，也可以直接在小程序注册新买家。

### 手机真机调试

手机中的 `127.0.0.1` 指向手机本身。将 `config.js` 的 `baseUrl` 改为电脑的局域网 IP，例如 `http://192.168.1.20:8080/api`，手机与电脑连接同一网络，并允许本机防火墙访问该端口。真实 AppID、调试权限及工具设置依微信开发者工具要求配置。

发布前需要 HTTPS 服务域名及微信后台的 request 合法域名配置，恢复域名检查，并完成相应业务资质和平台审核。后端现有演示账户、模拟付款及固定汇率应按正式业务要求替换。

## 演示顺序

1. 发现页选择“轻装出行”，打开商品详情并加购。
2. 登录后返回详情，点击加入购物车，进入购物车调整数量。
3. 去结算，选择美国 / 德国 / 英国及 USD / EUR / GBP，观察后端报价变化。
4. 填写收件人及完整地址，确认下单。购物车清空，订单变为待付款。
5. 我的订单中模拟付款。通过原 HarborCart 网页运营后台填写物流单号并发货，小程序下拉刷新后查看已发货状态。
6. 另建一笔待付款订单并取消，观察库存回补。

独立源码压缩包包含小程序与后端。原工作区 `frontend` 目录另有 Vue 运营后台，可按根目录说明启动。

## 已处理的业务细节

- `utils/api.js` 统一 Bearer 认证、网络超时、HTTP 错误。401 只清理与该请求匹配的登录态，避免旧响应清除新登录。
- 登录令牌保存在进程内存中，重启小程序需重新登录。退出会请求服务端撤销令牌。
- 购物车按整数分汇总展示小计，结算金额以服务端 `BigDecimal` 计算为准。
- 切换国家和币种时清空旧报价，通过请求版本号过滤迟到的旧响应。
- 下单之前按用户 ID 保存请求键和收件信息。超时、5xx 或页面重建后重试原请求，由服务端唯一约束避免重复订单。
- 待确认订单存在时，小程序限制加购和购物车变更。恢复确认时使用原始提交信息。该限制仅作用于当前客户端，跨客户端操作仍受后端事务和库存校验约束。
- 下单成功或明确的 400/409 拒绝后清理待提交记录。订单页查到同键订单时也清理记录。待确认期间本地保存收件信息，确认后删除。
- 后端仅允许取消待付款订单。页面按状态展示操作入口，后端再次检查订单归属和状态。
- 图片按后端已知六种商品图映射为本地 PNG，避免小程序 SVG 兼容性及外链图片域名配置问题。

## 验证

在 HarborCart 根目录执行。

```powershell
node --test miniprogram/tests/core.test.cjs
node miniprogram/tests/integration.cjs
```

第二条命令需要本机演示后端运行。它会创建一个唯一买家账户和两笔测试订单，保留一笔已发货订单和一笔已取消订单，并使一个商品库存净减少 1 件。脚本拒绝向非本机地址执行。

2026-11-10 验证结果

- 10 项 Node 自动检查通过。覆盖页面与图片文件、事件绑定名称、筛选排序、请求认证、401、网络超时、持久化请求键、报价乱序和重复提交。
- 使用真实 MySQL 和 Spring Boot 完成注册、商品加载、详情加购、购物车、报价、下单、同键重试、模拟付款、管理员权限、发货、取消回补、退出及令牌撤销联调。
- 联调运行的是实际页面逻辑与 `wx.request` 适配层，Node 中提供 wx 接口替身。当前环境没有微信开发者工具，因此原生 WXML 编译、微信模拟器渲染、手机真机操作仍需在导入后检查。
- 本次后端 Redis 未启动，联调验证了数据库回源路径。Redis 正常缓存路径沿用已有后端实现。

## 导入后的检查清单

- 首页、详情、购物车、订单和个人中心的中文布局及安全区。
- Android / iOS 输入框、键盘遮挡、picker 和订单确认弹窗。
- 登录取消返回、401 重新登录、下拉刷新与返回页面。
- 断网下单后恢复网络，重试原订单，确认订单数量与库存只变化一次。
- 后台修改库存后再次下单的校验结果。

## 面试讲解

可以介绍为 HarborCart 的微信小程序客户端，重点讲原生页面与组件、生命周期刷新、请求封装、状态管理、报价竞态和下单幂等。后端与网页端共享账户、商品和订单服务。

技术栈为 JavaScript / WXML / WXSS / 微信小程序 API / Spring Boot / MySQL / Redis。按自己的实际参与范围说明开发与 AI 辅助部分，真实支付、微信登录及线上用户规模需要以实际接入和数据为准。

参考文档：[网络请求](https://developers.weixin.qq.com/miniprogram/dev/api/network/request/wx.request.html)、[项目配置](https://developers.weixin.qq.com/miniprogram/dev/devtools/projectconfig.html)。
