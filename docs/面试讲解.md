# HarborCart 项目讲解与学习路线

## 一分钟介绍

HarborCart 是我用于学习 Java 全栈业务的跨境生活用品商城。前端使用 Vue 3 和 Vue Router，后端使用 Spring Boot 与 JDBC，MySQL 保存用户、商品、购物车、订单，Redis 缓存商品目录。它有面向买家的购物流程和中文运营后台，覆盖下单、模拟付款、取消和发货。我重点关注服务端计价、库存事务、订单状态与权限校验。项目是个人练习，没有真实商业交易或生产并发数据。

## 为什么与原有经历有关

我之前参与 Shopify 和 SHOPLINE 独立站开发，接触过商品详情、加购、抽屉购物车和多语言页面。这个项目把此前前端电商经验延伸到后端：订单由谁计价、库存何时扣减、重复下单如何处理、谁可以查看和操作订单。不要把它说成前公司的 Java 项目。

## 订单流程与事务边界

`PENDING → PAID → SHIPPED`；只有 `PENDING → CANCELLED` 可以取消。模拟付款不接支付服务。已付款不允许直接取消，也没有假装实现退款。

下单先锁用户行，序列化该用户的购物车修改与提交；检查 `(user_id, request_key)` 是否已有订单；再按商品 ID 顺序加行锁检查上架状态、库存和价格。在一个事务里创建订单和明细、条件扣减库存、清空购物车。任何一步失败，数据库整体回滚。锁顺序减少多个购物车交叉下单时的死锁机会；实际生产仍需对死锁做有限重试和监控。

为什么有行锁还要条件更新？行锁让当前流程看到稳定库存，`stock >= quantity` 条件是额外防线，避免未来其他代码路径绕过前置检查。商品表也有非负库存约束。

## 下单幂等

前端为一次结算意图生成 requestKey，提交重试复用它；后端使用用户行锁与数据库唯一约束共同保证同一用户同一键只生成一笔订单。重复请求返回原订单，不再次扣库存。请求键不是 Redis 临时锁，数据库才是最终约束。正式接口可额外保存请求摘要，拒绝“同一个键但不同的请求内容”。

## 取消回补

取消会锁定订单并检查归属；待付款才回补库存并改为已取消，已经取消再次请求直接返回。付款和取消都会锁同一订单，因此只有一个状态变更先成功。不会对已付款订单回补库存。

## 钱与跨境

后端统一以 BigDecimal 计价，USD 是商品基准价，兑换后的每件商品单价按 HALF_UP 保留两位，再乘数量汇总；运费也按币种换算。订单保存币种、固定汇率、商品名、成交单价和运费快照，之后改商品价格不会改变历史订单。销售额按币种分组，不能把美元和欧元直接相加。运费免邮阈值按 USD 基准小计判断。本项目没有真实汇率服务与进口税费计算。

## Redis 做什么

目录是公开高频读数据，Redis 使用 cache-aside：先查缓存，未命中读 MySQL 并设置 60 秒 TTL。修改商品或订单扣减、回补库存后，在数据库事务提交成功后删除缓存。不能在事务提交前删除：其他请求可能读到旧数据库并回填。

缓存不承诺强一致。读写竞争仍可能回填旧值，TTL 限制旧值持续时间。展示层可以接受短暂旧库存，结算不能，所以结算直接查 MySQL 并锁行。Redis 故障不会让用户无法浏览商品，而是降级查询 MySQL，30 秒后再尝试缓存。若流量升高，需评估穿透、击穿、热点互斥与回源限流，不能声称这些已经实现。

## 为什么没有 MyBatis Plus 和微服务

当前表和查询数量有限，Spring JDBC 的参数化 SQL、事务与显式行锁就能清楚表达业务。引入 MyBatis Plus 不是难点，也不是这个项目的亮点。如果岗位需要，可以基于现有 Service 边界逐步替换持久化代码。当前是单体，未引入消息队列、分布式事务或微服务，也没有编造对应经验。

## 登录与权限

密码用 BCrypt 保存；登录生成 256 bit 随机令牌，数据库保存其 SHA-256 摘要和过期时间。数据库泄露时无法直接拿摘要当作令牌使用。每次受保护请求核查令牌并读取当前用户角色；后端验证管理员权限。订单查询和操作都按 user_id 约束，不依靠前端隐藏按钮。退出删除令牌。它是 opaque token，不是 JWT；面试时要说准确。

## 前端可以讲什么

Vue Composition API 管理表单、列表和异步状态；Vue Router 做路由和访问引导；原生 fetch 统一处理错误与令牌。结算页以服务端报价显示金额，并通过请求版本号丢弃较晚返回的旧报价。商品详情用原生 dialog 支持 Escape 和焦点约束。移动端改变布局，商品图片为项目内 SVG，避免外部图片失效。

## 建议学习顺序

1. 用买家账户完整下单，再切运营账户发货，记录数据库每张表怎样变化。
2. 读 `schema.sql` 与 `ShopService.checkout`，手写一次下单流程图。
3. 理解 Spring Bean、依赖注入、`@Transactional` 代理与运行时异常回滚；注意事务方法必须经代理调用。
4. 跑后端测试，重点解释两个线程抢一件库存时发生了什么。
5. 打开 Redis 查看目录 key；编辑商品后观察删除、再次访问后回填与 TTL。
6. 独立修改一个运费规则并补测试；只有能自己修改和定位问题，才在面试中写“熟悉”。

## 简历不能写的内容

未经压测不要写“支持万级并发”“吞吐提升 80%”；没有上线不要写“日均百万订单”；没有接入真实支付不要写“完成支付平台对接”。AI 辅助开发不等同于独立熟练掌握，投递前至少能够演示、修改并解释核心流程。
